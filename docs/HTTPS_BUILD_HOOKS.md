# Optional HTTPS packaging hooks

The public repository contains all application code. A separate build-only
repository can check out a selected public branch, resolve and record its current
commit once, run its checks, and build that same checkout with optional inputs.
No application source overlay or string replacement is needed. These hooks do
not fetch credentials, contact an authentication service, or run a private build.
Existing public manual workflows are unchanged.

## Inputs

| Environment variable | Effect |
| --- | --- |
| `DIPLAY_HTTPS_DOMAIN` | Optional bare ASCII DNS hostname. Whitespace is trimmed and ASCII case normalized; default `tesla.mark4z.asia`. URL schemes, ports, paths, wildcards, Unicode, IP literals and invalid DNS labels are rejected. |
| `DIPLAY_HTTPS_ASSETS_DIR` | Optional external asset root containing only the selected `private-https/identity.zip` TLS bundle. Ordinary source builds have no bundled TLS identity. |
| `DIPLAY_AUTH_ASSETS_DIR` | Existing explicit external asset root containing `offline-mfi/identity.pk8` and `offline-mfi/certificate.p7b`. |
| `DIPLAY_PRIVATE_BUILD=true` | Release application ID suffix `.hudtest` and version suffix `-private`; the existing explicit release-signing environment inputs remain required. |

Do not commit real credential files or include them in source archives. APK
assets are extractable: bundling a TLS or accessory private key exposes it to
anyone who receives that APK. Limit distribution accordingly. Android signing
keys must never be included in APK assets. No key is generated by these hooks.

## One hostname throughout the installed APK

`:shared:generateBrowserHttpsConfig` writes one non-secret Java resource under
`shared/build/generated/browserHttpsResources/diplay-browser-https.properties`.
Its exact ASCII bytes are `hostname=<normalized-domain>\n`, where `\n` means a
single LF byte. Gradle registers that directory through
`sourceSets.main.resources.srcDir`, and both `preBuild` and Java-resource tasks
depend on generation. The APK contains it at the archive root, not in `assets/`.

`BrowserHttpsPolicy` reads this immutable classpath resource. The policy has no
Android or generated Java dependency and can still compile with standalone
`javac` together with `BrowserTlsIdentity` and `BrowserTlsBundle`. Without the
resource it uses the public default; malformed present resources fail closed.
A separate TLS validator must put `diplay-browser-https.properties` at the root
of its temporary classes directory or another runtime classpath entry, with the
same exact `hostname=<normalized-domain>\n` bytes. It must also pass that hostname
to `BrowserTlsBundle.read`. The explicit argument alone is insufficient:
`BrowserTlsIdentity` restricts validation to `BrowserHttpsPolicy.HOSTNAME`, so a
custom-domain validator without the matching resource correctly fails closed.
Remove this temporary validator directory after the build.

`BrowserViewerAssets` uses this same policy for its Host/Origin validation and
its exact-host WSS-only CSP response header. It synthesizes the served
`/config.mjs` from the policy; static packaged viewer files remain byte-for-byte
identical to source. The standalone public website uses its checked-in default
`config.mjs`. Neither URL parameters nor browser storage select a hostname.

The HTML meta CSP continues to support the external LAN viewer's `ws:` policy,
which already includes its secure upgrade. APK responses intersect that policy
with an exact-host WSS-only header. There is no plaintext fallback for the
embedded viewer. Port `9999` and VPN addresses remain unchanged.

## Optional bundled TLS bootstrap

When there is no saved identity and no import is pending, `BrowserTlsStore`
may read the explicitly bundled ZIP once. It applies the same archive-size,
certificate trust, validity, SAN hostname and key-match checks as a manual
import, then encrypts it in the app's no-backup storage. Existing saved identities
take precedence; corrupt saved data is not silently replaced. Input buffers are
wiped. Deleting HTTPS setup persistently disables bootstrap until app data is
cleared, while later manual imports remain available. This does not delete the
original APK asset or make a bundled key unextractable.

## Verification contract

- Run public Python tests and `node --test site/browser-carplay/tests/*.test.mjs`.
- Run `:shared:testDebugUnitTest` and `:common:testDebugUnitTest` plus the desired
  Android lint/build tasks on GitHub Actions. The policy test asserts that the
  generated resource is on the JVM classpath; store tests use synthetic data.
- `scripts/check_embedded_viewer_apk.py` checks credential-free source APKs for
  the exact canonical viewer set and a unique generated hostname resource. It
  rejects every `assets/private-https/` entry, including a TLS ZIP. Python callers
  checking a credential-free build with another hostname pass
  `verify(apk, source, hostname=normalized_domain)`; private builds require their
  own credential-aware artifact checker.
- A private packager must additionally verify its exact intended credential
  assets and Android signing certificate, then remove temporary credentials and
  credential-bearing build intermediates without caching or uploading them.
- Verify a custom-domain APK's root resource is exactly
  `hostname=<requested normalized domain>\n`. Missing or duplicate resources,
  a fallback default, or a mismatching hostname must block artifact publication.

An APK/resource check cannot prove real-device DNS, certificate trust, VPN or
in-car browser compatibility. Those still require device testing.
